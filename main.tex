\cvsection{Projects \& Open Source --- References}

\noindent Everything on this page is public unless marked otherwise, and each figure comes from the benchmark published in its repository. Pilot Space (\href{https://github.com/pilotspace}{github.com/pilotspace}) is my own open-source line of AI infrastructure, built since January 2026.

\work{Moon}{\href{https://github.com/pilotspace/moon}{github.com/pilotspace/moon} · docs \href{https://pilotspace.github.io/moon/}{pilotspace.github.io/moon} · \textit{moondb} on crates.io and PyPI}{A Redis-compatible in-memory data store written from scratch in Rust, so existing Redis clients connect unchanged: RESP2 and RESP3, 250+ commands. Vector search (HNSW), BM25 full-text search with hybrid rank fusion, a property-graph engine and transactions that hold across all of them ship in one binary. \work{Lunaris}{\href{https://github.com/pilotspace/lunaris}{github.com/pilotspace/lunaris} · docs \href{https://pilotspace.github.io/lunaris/}{pilotspace.github.io/lunaris} · \textit{lunaris-memory} on crates.io, \textit{@pilotspace/lunaris} on npm}{An agent-memory engine built on Moon: ingestion, extraction, embeddings, hybrid search and re-ranking behind one API, with the embedding and re-ranking models running in-process so recall makes no network call. Recall across 100,000 documents per scope returns in 19--22\,ms at the median and under 25\,ms at P99 on a single shard; beyond 100,000 documents it is published as unvalidated. A CI gate scores evidence recall on LongMemEval-S on every retrieval change and fails the build when recall drops. I wrote that gate after finding its predecessor had never once run --- all 200 recorded executions were startup failures.}

\work{laya-codex}{\href{https://github.com/pilotspace/laya-codex}{github.com/pilotspace/laya-codex} · model \href{https://huggingface.co/tindang/laya-code}{huggingface.co/tindang/laya-code}}{Ranked code retrieval for coding agents. The repository is split into chunks with tree-sitter (14 languages), keyword search finds candidates, and a cross-encoder re-ranker I fine-tuned on git history --- where a commit's changed code is the answer to its message --- orders them and places the code in the agent's first turn through hooks and MCP. On 60 paired tasks across 3 repositories the right files appeared in the first answer 88\% of the time, up from 73\%; tool calls per session fell from 5.9 to 2.3, session time by 19\% and cost by 14.8\%. On 60 further tasks the cost gain was not significant, and the README says so.}

\cvsection{How I Evaluate}

\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=1pt,parsep=0pt]
  \item \win{Gate quality in CI.} In Lunaris every change to retrieval is scored for evidence recall, and the build fails when recall drops.
  \item \win{Pair the tasks and state the interval.} The laya-codex benchmark runs the same 60 tasks with and without the tool, reports a 95\% confidence interval, and repeats on 60 new tasks.
  \item \win{Publish the result that goes against you.} ADD is published with its price, Moon lists the command families where it loses to Redis, and Lunaris marks everything beyond 100,000 documents as unvalidated.
  \item \win{Reconcile against an outside source.} At ClickAI I checked metered LLM cost against the providers' own bills, which is how a 30\% drift surfaced that no internal metric showed.
\end{itemize}
